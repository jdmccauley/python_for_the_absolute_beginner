Chapter 5 Notes - Lists and Dictionaries

Lists
Lists are sequences just like tuples, but they are mutable. Elements can be added, removed, and edited. Lists can even be sorted!
Most apparent difference is that you use brackets [] with lists instead of parentheses () with tuples.
To go over a few functions that are the same as with tuple:
	len()
		Running len() for a list is the same as running it on a tuple. The output is the number of elements.
	in operator
		You can run an if statment or for loop to see if an element is contained in the list.
			All you have to do is run:
			if (for) [element] in [list]
	Indexing
		Accessing one element of the list is the same as with the tuple, just use:
			command(list_or_tuple[index])
	Slicing
		This works the same with tuples and lists.
		Slice  = list_or_tuple[start:end:step]
	Concatenating
		Same with lists as with tuples:
		list1 = list_2 + list_3
		The only thing to remember is that you can't concatenate tuples and lists together. The sequeces to concatenate must
			be of the same type.

List mutability
This is the main difference between tuples and lists. You can change an element in a list, and add/remove elements.
To reassign an element to the list, just assign by the index:
	list[index] = new_value
You can do this for slices as well. Say for example this list is 4 long:
	list[1:3] = new_value
	Now the second and third elements in the lists got replaced with new_value. list[1] and list[2] = new_value
	print(list) -> new_value, list[3], list[4]
You can delete an element in the list by using del:
	del list[element]
	This removes the element and does not leave a gap. Because of this, the indexes of the list are reassigned to reflect the removal.
	This method is for deleting a specific element by index. More on element deletion by element value later.
Deleting slices works the same way:
	del list[beginning:end:step]

List Methods
The standard python library comes with functions for lists, and you can call them by using 'list_name.function_name()'.
What's nice about this is that the function is called with the list name as the first part before the '.', not a module name.
Here are a few of the standard list functions and how to use them:
	list_name.append(element)
		This adds a new element to the list at its end. Note that this can only be used one element at a time.
		Use a loop or statement to repeatedly add elements.
		For example:
			list_josh = ["j", "o", "s", "h"]
			print(list_josh) -> ["j", "o", "s", "h"]
			list_josh.append("u")
			list_josh.append("u")
			print(list_josh) -> ["j", "o", "s", "h", "u", "a"]
	list_name.remove(element)
		This deletes the element from the list by giving the element value as the argument.
		It works by iterating over the list and checks if the element is the same as the argument, then deletes the element if true.
		Only runs once and works on the first time that the element is seen.
		To do multiple times, use a loop or statement.
		To do this in a loop only if the element is in the list, use:
			if element in list:
				list.remove(element)
	list.sort(args)
		Without any argument, this sorts the list (and reindexes the elements) from least to greatest.
		To go from greatest to least, use this:
			list.sort(reverse = True)
	list.reverse()
		This reverses the order of the list. It's the same as list.sort(reverse = True), just less time to type.
	list.count(element)
		This counts the number of times that the element is in the list.
	list.index(element)
		This returns the index of the element.
	list.insert(index,element)
		This inserts the element at the index. Does not remove the element previously at the index.
		The elements after the insertion are reindexed to reflect the insertion.
	list.pop(index)
		This returns the element at the index, and removes that element from the list.

Lists vs Tuples
Generally, lists can do everything that tuples can plus more. But tuples do have a place in python despite lists being very similar.
Here are some of the reasons to use tuples:
	memory allocation
		Since tuples are not mutable, their memory is allocated such that they are faster to access than lists.
		For complex programs, this memory retieval time difference can matter.
	constant
		Tuples are not mutable, so sometimes it makes sense to use them for variables that aren't meant to change.
		This saves accidental editing of sequences that would be edited if they were lists.
	function requirements
		Some functions require immutable sequences (like dictionaries). This is a case where you can use a tuple but not a list.
Lists do make more sense most of the time, but tuples are important to remember for cases where those reasons apply.

Nested Sequences
Since tuples and lists are sequences, their elements can be tuples and lists too.
Embedded sequences can be very helpful, just remember which levels are mutable.
For accessing specific elements in nested sequences, provide the number of indexes as levels deep the element is.
	For example:
		level_1 = ["level", "one"]
		level_2 = [level_1, "level", "2"]
		print(level_2[0][1]) -> "one"
	This works by accessing element zero in level_2, which is level_1, and element 1 within level_1_.

Sequence Unpacking
Unpacking a sequence is a way to assign values to all elements in a sequence for addition of a nested sequence.
This only works when you assign a value to each element of the nested sequence. Here is an example:
	nested_list = ["list_1_element_1", list_1_element_2"]
	element_1, element_2 = ("list_2_element_1", "list_2_element_2")
	list_2 = [element_1, element_2]
	nested_list.append(list_2)
	print(nested_list) -> [["list_1_element_1", list_1_element_2"], ["list_2_element_1", "list_2_element_2"]]
I believe the order does not matter, you just need to have the same number of elements as the sequence.

References
Python variables are not like typical variables in other languages like C. Python variables are actually pointers to values stores in memory.
This is where mutable and immutable variables really show their difference.
Immutable variables are given a new memory address when they are assigned and reassigned.
	If two variables have the same value, they have the same addresss.
	Since variables are pointers to an address, variables with the same value are given the same address instead of
		allocating new memory for the same value.
	But when you change the value of one variable, it is given a new address and a new value independent of the other.
Mutable variables are given a new memory address when they are assigned and reassigned, but when they are edited, the address remains the same.
	This is important, since immutable variables cannot have the value at an address changed.
If you make an immutable equal to an other immutable variable, their addresses will be the same.
	But if you reassign the new variable (the one made equal to the original variable), it will have a new address (and value), while the 
		address and value of the original variable will remain the same as before.
	Edits to a value at an address are not possible without a module importing C-like functions.
If you make a mutable variable equal to another mutable variable, their addresses will be the same.
	If you edit (not reassign) the new variable (the one made equal to the original variable), it will have the same address and a different value.
		The original variable will have the same new value and same original address, since these variables are linked by memory address.
The important thing to highlight here is that if you assign a mutable variable to a mutable variable, any edits to one occurs to the other
	since they are both given the same address.
	Edits, not reassignments, do this. See below.
	edit:
		list = [1]
		list[0] = 2
	reassignemnt:
		list = [1]
		list = [2]
This is very different to C, where making a variable equal to another in C gives each variable a different address,
	and changes to the new variable to not change the original variable.
	However, with the use of pointers you can change values at one variable's address with another variable technically.
Python gives the same address to variables with the same value, and changes the address when one is reassigned.
	It keeps the same address to variables when the value is edited, where only mutable variable types can have values edited.
In C, every variable gets its own address by default.
To sum this all up, python variables are actually references to memory addresses that store values.
	Declaring a new variable does not allocate memory implicitly, it allocates memory if the value is unique.
	This saves memory allocation, but you can edit a variable's value if the value at it's address is changed.
C on the other hand sets up memory for every single variable, even if values of variables are the same.
	This makes for redundant memory allocation, but you can't change a variable's value without calling it.

To make a mutable variable that is a copy of another mutable variable, and have the variables not be linked or have
	the same memory address, use slices:
	mutable_variable_2 = mutable_variable_1[:]
	This makes the mutable_variable_2 a copy of the value of mutable_variable_1 in a new address. This way, edits to each variable
	does not change the other.

Dictionaries
Dictionaries in python are another type of variable that contain more than one value, like lists and tuples. 
Dictionaries are variables with pairs of values: a 'key' and a 'value'. 
	This is like a dictionary book, where each 'word' has a 'definition'.
Each pair of values in the dictionary is called an 'item'. So a dictionary can have an infinite amount of items, as long as each item
	has one key and one value.
To make a dictionary, you must use colons and curly brackets:
	dictionary = {"key_1": "value_1", "key_2": "value_2}
Calling values in dictionaries is done like with tuples and lists, but you call the key instead of the index:
	dictionary["key_1"] -> "value_1"
	They dictionary[key] outputs the value associated with the key.
	Note that you use the key, not the index. This is great because you don't have to know the index like you do for lists/tuples.
	Dictionaries don't have indexes at all actually.
	You cannot pass a value to get the key however, that us important to note (you can do this with lists using list.index(value))
Like lists, you can test if keys are in a dictionary by using the 'in' operator:
	if key_name in dictionary_name:
		action
	else:
		other_action
Alternatively, you can use the dictionary function get(), more on that later.
Important things to note about making dictionaries:
	keys must be unique
		You cannot have multiple of the same key in the dictionary. If you add a key already in the dictionary, the old one will be deleted.
	keys have to be immutable
		You can make the key an integer, string, or tuple, but not a list. Keys cannot be mutable data structures.
	values don't have to be unique
		Since values are attached to unique keys, values can be duplicated across the dictionary.

Dictionary Methods
	dictionary_name.get(key_name, value_if_false)
		This returns the value if the key exists in the dictionary, and returns the value_if_false when the key is not in the dictionary.
		By default, the value if false is "None", but you can pass a value if desired.
	dictionary_name.keys()
		This prints all of the keys in the dictionary.
	dictionary_name.values()
		This returns all of the values in the dictionary.
	dictionary_name.items()
		This returns all of the key/value pairs in the dictionary.

Note that items, keys, and values can be iterated with for loops. They cannot be called by index, but you
	can view them all by printing each iteration in the for loop.
	Examples:
		for i in dictionary.keys():
			print(i)
		for i in dictionary.values():
			print(i)
		for i in dictionary.items():
			print(i)
	If you just try to iterate over the dictionary without a method, you get each key.
		for i in dictionary:
			print(i)
	That gets each key in the dictionary.
